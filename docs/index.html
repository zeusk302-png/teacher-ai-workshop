연수 홈 / 개념 이해

RAG와 NotebookLM

RAG 구축에 필요한 구성과 도구별 역할을 이해하고, 학교 양식 문서 작성으로 연결합니다.

왜 필요한가

데이터가 필요한 이유

자료를 연결하지 않은 AI 답변에는 학교별 규정이나 적용 연도가 빠질 수 있습니다.

같은 질문

“수행평가에 결시한 학생의 추가 평가 원칙을 정리해 줘.”

자료 없이 질문

어느 학교·어느 학년도의 규정인지 알려주지 않았습니다. 일반적인 설명이 나오더라도 우리 학교에 적용되는지 확인하기 어렵습니다.

자료를 검색해 질문

학교규정집과 적용 지침에서 질문에 맞는 내용을 찾고, 검색한 내용을 활용해 답변을 구성할 수 있습니다. RAG는 이처럼 검색한 내용을 AI 입력에 함께 제공하는 방식입니다.

RAG는 Retrieval-Augmented Generation의 줄임말입니다. 질문에 관련된 자료를 검색해 AI에 맥락으로 제공하고, 이를 활용해 답변을 생성하는 방식입니다.

개념 출처: NIST RAG 정의 · 위 질문과 두 상황은 연수용 예시이며 실제 규정 답변이 아닙니다.

검색 전 확인

믿을 수 있는 자료, 적용 시점, 질문에 필요한 소스 범위. 잘못되거나 관련 없는 자료를 찾으면 답변도 빗나갈 수 있습니다.

검색·생성 후 확인

인용이 실제 주장을 뒷받침하는지, 예외·조건이 빠지지 않았는지 원문을 대조합니다. RAG는 정확성을 자동으로 보증하지 않습니다.

자료를 넣는 것과 모델을 추가 학습시키는 것은 다른가요?

RAG의 핵심은 답변할 때 관련 자료를 찾아 제공하는 데 있습니다. 자료를 등록했다는 이유만으로 모델 자체가 다시 학습되거나 내용을 영구히 기억한다고 볼 수는 없습니다.

출처: Google Cloud RAG 설명, NIST 정의 · 이 흐름은 개념 설명이며 NotebookLM 내부 알고리즘의 상세 구조를 단정하는 도식이 아닙니다.

직접 구축할 때 필요한 것

검색부터 모델 연결과 운영까지 준비합니다

RAG를 직접 만들려면 자료, 검색 기능, 생성 모델과 이들을 연결할 프로그램이 필요합니다.

모델 API를 사용하면 모델을 실행할 GPU를 직접 갖추지 않아도 됩니다. 검색도 키워드 방식으로 구성할 수 있으며, 의미 검색을 선택할 때 임베딩과 벡터 검색 기능이 필요합니다. 별도 벡터 데이터베이스가 모든 RAG의 필수 조건은 아닙니다. 규모와 선택한 모델·검색 방식에 따라 필요한 자원이 달라집니다.

RAG와 NotebookLM은 어떤 관계인가요?

RAG는 검색한 내용을 생성 모델의 입력에 제공하는 설계 방식입니다. NotebookLM은 자료 등록·검색·정리 기능을 제공하는 제품입니다. 자료를 등록했다고 모델을 다시 학습한 것은 아니며, NotebookLM 실습을 자체 RAG 시스템 개발과 동일하게 설명하지 않습니다.

출처: NIST RAG 정의 · Microsoft RAG 구성·검색·운영 안내. NotebookLM의 내부 검색 알고리즘을 단정하는 설명은 아닙니다.

양식은 문서의 구조

제목·항목·표·결재란처럼 유지할 모양을 정합니다. 검색용 PDF와 편집할 원본 양식의 역할을 구분합니다.

스킬은 작업 절차

지원되는 환경에서 문서를 읽고 만들고 검사하는 지침과 도구입니다. 자료 검색이나 파일 생성 기능을 지시문만으로 새로 만들지는 않습니다.

연결 범위 이 실습은 기성 서비스를 조합한 업무 흐름입니다. 두 서비스 사이의 전달은 사람이 하며, 외부 AI가 원래 노트북 전체를 자동 검색하도록 연결한 시스템은 아닙니다.

제품 기능: Google 소스 기반 채팅·인용 안내 · 역할 분담은 이번 연수의 진행 방식입니다. NotebookLM에도 문서 생성 관련 기능이 추가되고 있으므로 제품 간 기능을 고정된 경계로 설명하지 않습니다.

검색을 문서 작성으로 연결하기

외부 AI가 바로 작업할 수 있는 요청을 만듭니다

업무 상황을 설명하면 NotebookLM이 관련 자료를 찾고, 외부 AI에 전달할 작성 요청을 정리하도록 합니다.

  1. 자료에서 찾을 내용

    적용할 지침, 원본 서식의 필수 항목, 기존 문서의 작성 방식. 필요한 원문 발췌와 자료명·쪽도 요청에 넣습니다.

  2. 이번 업무의 입력값

    목적·일시·장소·대상·인원·예산을 따로 적습니다. 기존 예시의 날짜·이름·금액을 이번 업무 사실로 옮기지 않습니다.

  3. 작성 조건과 검토 기준

    유지할 항목·표 구조·출력 형식, 미확정 정보 처리, 날짜·시간·총인원 검사 방법을 지정합니다.

  4. 함께 전달할 파일

    외부 AI에 작성 요청과 필요한 원문, 원본 양식을 함께 전달합니다. NotebookLM의 인용 번호만으로 원문 전체가 전달되지는 않습니다.

NotebookLM에 할 요청

“등록한 지침·작성 예시·양식을 참고해서, 이번 업무 문서를 외부 AI로 완성할 작업 지시문을 만들어 줘. 항목별 작성 내용, 필요한 원문 발췌, 추가 입력할 정보와 파일 검토 기준을 포함해 줘.”

실제 테스트에서는 어디까지 확인했나요?

2026.10.18. 현장체험학습 매뉴얼의 「서식 7: 사전답사 계획서」로 테스트했습니다. NotebookLM이 작성 요청을 만들고, 외부 AI에 요청과 원본 PDF를 전달해 DOCX·PDF를 생성했습니다. 가상 사례의 날짜·시간·인원을 바꾸자 본문과 일정표에도 반영됐고, 이전 값이 남지 않았는지 검사했습니다.

이 테스트는 Claude Pro 계정에서 PDF 서식을 DOCX로 재구성한 사례입니다. HWPX 원본 양식 보존이나 무료 계정에서의 동일 실행까지 검증한 결과는 아닙니다.

학교 업무 활용

검색 결과와 완성 문서를 검토합니다

검색한 원문 두 곳을 확인하고, 완성한 문서에는 바뀐 조건과 이전 값이 남지 않았는지 대조합니다.

  1. 질문의 범위를 정하기

    학교급·업무·적용 학년도를 적습니다. “규정 알려줘”보다 구체적으로 묻습니다.

  2. 관련 소스만 선택하기

    학교규정집·개정 사항·교육청 지침을 구분합니다. 관계없는 자료를 함께 적용하지 않습니다.

  3. 인용 두 곳을 직접 열기

    답변과 원문의 문맥을 비교합니다. 날짜·숫자·예외·적용 대상이 맞는지 확인합니다.

  4. 모르는 내용은 확인 필요로 남기기

    자료에 없는 담당자·일정·기관 승인 여부를 만들어 채우지 않습니다. 실제 업무 적용은 담당자가 검토합니다.

내용은 맞아 보이는데 인용만 있으면 충분한가요?

인용은 검증할 수 있는 길을 제공합니다. 인용된 문장이 답변을 뒷받침하는지 확인하는 일은 여전히 필요합니다. 자료 자체의 최신성·적용 범위도 함께 확인하세요.

확인 문제

학교규정집을 올린 뒤, 답변에 인용이 붙었습니다. 이제 바로 업무에 사용해도 될까요?

해설

아직입니다. 인용의 원문과 문맥, 적용 시점, 누락된 조건을 대조하고 실제 업무 사용 전 담당자가 검토합니다.

원문 확인 기능: Google 인용 안내 · 업무 절차와 확인 질문은 연수용 구성입니다.
